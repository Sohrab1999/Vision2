- **تاریخ تدوین:** ۲۰۲۶-۱۰-۰۹
- **نگارش:** v1.0

## ۰) خلاصهٔ وضعیت فعلی محصول (Baseline)

| محور | ارزیابی | شواهد |
|---|---|---|
| بلوغ محتوا | ۹۰٪ | ۳ درس، ۶۳۳ واژه، ۴۹۰+ تست، مکالمه/ریدینگ/گرامر تشریحی، ضمیمهٔ کامل |
| بلوغ موتور تمرین | ۸۵٪ | آزمون‌ساز + بانک اشتباهات + دیکتهٔ TTS + فلش‌کارت SRS + چالش ۶۰ثانیه‌ای با کمبو |
| گیمیفیکیشن | ۸۵٪ | ۲۱ نشان + ۵ هدف روزانه + زنجیره + جدول رده‌بندی DB-پشتیبان + پاداش نشان |
| داده و تحلیل خودِ کاربر | ۷۰٪ | نمودار ۷/۳۰ روز، دونات واژگان، رادار مهارت، کارنامهٔ چاپی — ولی «تحلیل در سطح واژه» صفر است |
| اعتماد و مالکیت داده | ۴۵٪ | بدون auth؛ پیشرفت تک‌دستگاهی؛ (فاز ۰: rate-limit + error boundary ✅ انجام شد) |
| حلقهٔ بازگشت کاربر | ۳۰٪ | هیچ یادآور/نوتیف/برنامهٔ بازگشتی وجود ندارد؛ SRS بدون اعلان عملاً «اگر یادت بود» است |
| زیرساخت تکرارپذیر | ۴۰٪ | فقط ۱ تست واحد (rate-limit)؛ بدون smoke test؛ بدون analytics |

**جمع‌بندی استراتژیک:** محصول یک «MVP++ بالغ» است؛ مشکلی در عرضهٔ محتوا و لذت تمرین ندارد. دو شکاف استراتژیک دارد: **(۱) ماندگاری** (کاربر برنمی‌گردد چون چیزی او را صدا نمی‌زند) و **(۲) اعتماد به داده** (پیشرفت گروگانِ یک مرورگر است). نقشهٔ راه زیر دقیقاً به همین دو شکاف و سپس تمایز AI متمرکز است.

## ۱) تحلیل وضعیت فعلی — نقاط ضعف و رفتارهای ناقص/دستی

### نقاط ضعف تجربهٔ کاربر (از QA زندهٔ امروز)
- [x] **نقطهٔ صفر بی‌هدف:** کاربر تازه‌وارد با صفحهٔ شلوغ ۱۷ناحیه‌ای تنها می‌ماند؛ هیچ آنبردینگی «از کجا شروع کنم؟» را جواب نمی‌دهد *(حل: فیچر F1)*
- [x] **پنل کنترل صفر:** کاربر هیچ تنظیمی ندارد (سرعت روخوانی، اندازهٔ فونت، افکت صدا، خروج داده) *(حل: F2)*
- [x] **ناسازگاری محتوایی:** تست‌های درس ترجمهٔ فارسی دارند ولی بانک ۳۶۰تایی آزمون جامع ندارد *(حل: F5)*
- [x] **فید/جدول بدون احساس مالکیت:** جدول رده‌بندی می‌تواند با شناسهٔ کلاینتی آلوده شود؛ ریسک اعتماد (مالی/اعتباری) *(حل: F3)*
- [ ] پولینگ فید/جدول با فرکانس ثابت — در لاگ سرور فراخوانی‌های مکرر `/api/leaderboard` دیده شد؛ کاندیدای بهینه‌سازی (adaptive interval وقتی تب مخفی است) — **اولویت پایین، در فاز بهینه‌سازی**
- [ ] میان‌بر `?` روی کیبورد فارسی کار نمی‌کند (یافتهٔ ممیزی؛ کم‌اهمیت)

### رفتارهای ناقص یا دستی کاربر
- کاربر برای انتقال پیشرفت باید از دکمهٔ پشتیبان‌گیری دستی استفاده کند → خروجی JSON را خودش جابه‌جا کند (رفتار ۱۰۰٪ دستی) *(حل: F3)*
- کاربر برای فهمیدن «چرا غلط زدم؟» فقط گزینهٔ درست را می‌بیند؛ هیچ توضیحی نیست *(حل: F8)*
- کاربر برای تمرین شنیداری فقط دیکته دارد؛ آزمون‌های واقعی Vision مهارت Listening دارند و اپ پوشش نمی‌دهد *(حل: F6)*
- معلم/والد هیچ ابزاری ندارد؛ اپ فقط تک‌شخصی است *(حل بلندمدت: Teacher Mode — فعلاً رد شده، بند ⛔)*

## ۳) کارت‌های فیچر پیشنهادی (به‌تفصیل)

### F1 — آنبردینگ ۳مرحله‌ای + هدف روزانهٔ انتخابی 🟡 🟢
- **مشکلی که حل می‌کند:** ابهام شروع؛ روز اولِ بدون جهت = ریزش.
- **سناریو:** اولین بازدید → (۱) نام و رنگ را انتخاب کن (همان پروفایل موجود) → (۲) هدف روزانه: ۵/۱۰/۱۵ فعالیت → (۳) یک فعالیت راهنمادار (فلش‌کارت) با فلش‌های اشاره → ثبت نشان «اولین قدم».
- **ارزش:** فعال‌سازی روز اول؛ هدفِ انتخابی حس مالکیت می‌سازد (قاعدهٔ Escalation of Commitment).
- **پیچیدگی:** **Low** — همهٔ اجزایش (پروفایل، اهداف، نشان اول) موجودند؛ فقط جریان + پرچم «دیده‌شده» در استور.
- **ریسک/هزینه:** ناچیز؛ فقط نباید مزاحم کاربر برگشتی شود (شرط: فقط بار اول).
- **فاز:** ✅ مناسب MVP — **اولین کار پس از این سند.**

### F2 — مرکز تنظیمات (Settings Hub) 🟡
- **مشکل:** کاربر هیچ کنترلی روی سرعت روخوانی، اندازهٔ متن، افکت‌های صوتی، حرکت انیمیشن ندارد؛ دسترس‌پذیری صفر.
- **سناریو:** دانش‌آموز کم‌بینا فونت را ۱۸→۲۲ می‌برد؛ دانش‌آموزی که در کتابخانه است صدای UI را خاموش می‌کند؛ همه در یک پاپ‌آور «تنظیمات».
- **ارزش:** حس حرفه‌ای بودن + دسترس‌پذیری + کاهش نارضایتی پنهان.
- **پیچیدگی:** **Low** — TTS از beforeقبال `speak.ts` سرعت می‌پذیرد؛ فونت با CSS variable؛ صدا/حرکت با استور.
- **ریسک:** تنظیمات دارک/فونت با override های دستی دارک فعلی برخورد نکند → تست روی ۷ تب.
- **فاز:** ✅ MVP.

### F3 — «کد یادگیرنده»: همگام‌سازی و بازیابی پیشرفت بین دستگاه‌ها 🔴
- **مشکل:** پیشرفت گروگان مرورگر است؛ پاک‌شدن دیتا = سوختن زحمت چند هفته؛ انتقال دستی JSON مخصوص آدم‌های فنی است.
- **سناریو:** کاربر در پروفایل «کد من» را می‌گیرد (۶-۸ کاراکتر)؛ روی دستگاه دوم همان کد را وارد می‌کند → سرور اسنپ‌شات استور را برمی‌گرداند/merge می‌کند → پیشرفت یکپارچه.
- **ارزش:** حیاتی‌ترین فیچر اعتماد؛ پیش‌نیاز واقعی‌شدن جدول رده‌بندی؛ ترس از «گم‌شدن» را حذف می‌کند.
- **پیچیدگی:** **Medium** — endpoint backup/restore (پشتوانه: سیستم پشتیبان خودکار موجود) + فرم‌ها + قواعد merge (last-write-wins روی فیلدهای عددی، union روی مجموعه‌ها) + rate-limit سخت روی حدس کد.
- **ریسک:** برخورد merge؛ اشتباه تایپ کد (باید تأیید دوپله‌ای نمایشی داشته باشد)؛ نباید جایی جایگزین auth سنگین شود.
- **فاز:** ✅ MVP (نیمهٔ دوم) — این همان «ownership سبک» فاز ۱ ممیزی است.

### F4 — PWA نصب‌پذیر + نشانگر سررسید مرور 🟢
- **مشکل:** اپ نصب‌پذیر نیست؛ آیکون گوشی ندارد؛ هنگام آفلاین فقط خطا می‌دهد؛ کاربر هرگز «سررسید مرورش» را نمی‌بیند مگر اپ را باز کند.
- **سناریو:** «افزودن به صفحهٔ اصلی» → آیکون و اسپلش برند → باز شدن به‌صورت اپ مستقل → بدج لروی آیکون «۳۷ واژه سررسید» هنگام باز کردن.
- **ارزش:** ماندگاری (presence روی گوشی) + قدم اول حلقهٔ بازگشت؛ آفلاینِ حداقلی برای محتوای کش‌شده.
- **پیچیدگی:** **Medium** — manifest + service worker (Next 16) + استراتژی cache-safe برای APIها؛ بدج از دادهٔ SRS استور (بدون سرور).
- **ریسک:** کشِ منقضی بعد از دیپلوی (بای‌پس در dev)؛ iOS محدودیت‌های خاص خودش را دارد.
- **فاز:** 🟡 فاز ۲ (اولین قدم حلقهٔ بازگشت).

### F5 — ترجمهٔ فارسی بانک ۳۶۰ (فازبندی ۱۰۰ → ۳۶۰) ✅
- **مشکل:** تجربهٔ ناسازگار: تست درس ترجمه دارد، آزمون جامع ندارد → احساس «نصفه» بودن.
- **سناریو:** پاسخ‌گویی به تست آزمون جامع، توضیح فارسی زیر گزینهٔ درست — مثل تست‌های درس.
- **ارزش:** کیفیت درک؛ اعتماد محتوایی؛ کاهش فشار شناختی دانش‌آموز ضعیف‌تر.
- **پیچیدگی:** **Low-Medium** — کار محتوایی فازبندی‌شده؛ زیرساخت data موجود (`QuizQuestion.fa` وجود دارد).
- **ریسک:** خطای ترجمهٔ انسانی → قالب واژه‌نامه‌محور + بازبینی.
- **فاز:** ✅ کامل شد — ۳۶۰/۳۶۰ (فاز ۳: x-201..x-360 — ۲۰۲۶-۱۰-۱۰، Task 24) + اصلاح ۲ کلید خطادارِ انتقال (x-296، x-353).

### F6 — تمرین شنیداری «بشنو و انتخاب کن» 🟡 🟢
- **مشکل:** امتحان واقعی Vision مهارت شنیداری دارد؛ اپ فقط دیکته دارد (تولید متن، نه درک مطلب).
- **سناریو:** TTS جمله/دیالوگ را می‌خواند (حداکثر ۲ بار) → ۳ گزینه (ترجمهٔ درست / ادامهٔ جمله / تصویر-واژه) → فیدبک فوری → ثبت در SRS و مهارت listening.
- **ارزش:** هم‌راستایی با ارزیابی مدرسه؛ تمایز نسبت به وبکتاب‌های صرفاً متنی؛ استفادهٔ مجدد از موتور TTS و آزمون‌ساز موجود.
- **پیچیدگی:** **Medium** — موتور جدید ولی بر پایهٔ quiz-engine؛ محتوا از جمله‌های مکالمه/ریدینگ موجود استخراج می‌شود (بدون تولید محتوای بیرونی).
- **ریسک:** کیفیت TTS برای جمله‌های بلند؛ سکوتِ شبکه در تماس‌های تکراری (کش TTS موجود مشکل را حل می‌کند).
- **فاز:** 🟡 فاز ۲-۳.

### F7 — «واژه‌های خطرناک من»: تحلیل اشتباه در سطح واژه 🔵
- **مشکل:** `QuizAttempt` فقط نمره می‌داند؛ کاربر نمی‌فهمد کدام ۱۰ واژه بیشترین ضربه را به او زده؛ بانک اشتباهات فقط «تست» را نگه می‌دارد نه الگو را.
- **سناریو:** پنل «واژه‌های خطرناک» با ۱۰ واژهٔ بیشترین خطا + نرخ خطای هر کدام + دکمهٔ «فلش‌کارت همین‌ها» و «تمرین همین‌ها» → بستن حلقه با SRS.
- **ارزش:** شخصی‌سازی واقعی یادگیری؛ دلیلی که کاربر حس کند «اپ من را می‌شناسد».
- **پیچیدگی:** **Medium** — گسترش payload ثبت نتیجه (آرایهٔ شناسه‌های غلط) + انباشت سرور/کلاینت + UI پنل.
- **ریسک:** رشد حجم رکورد → سقف ۵۰ شناسه در هر ثبت؛ محاسبهٔ انباشتی در کلاینت از دادهٔ خود کاربر.
- **فاز:** 🔵 فاز ۲-۳.

### F8 — «چرا غلط شد؟» توضیح هوشمند خطا (AI Explain) 🔵 — تمایز استراتژیک
- **مشکل:** بعد از جواب غلط فقط گزینهٔ درست نمایش داده می‌شود؛ دانش‌آموز «چرا» را نمی‌فهمد؛ هیچ معلمی در ۱۱ شب در دسترس نیست.
- **سناریو:** زیر فیدبک تست، دکمهٔ «توضیح با هوش مصنوعی» → درخواست به `/api/explain` → توضیح ۲-۳ خطی فارسیِ ساده (قاعدهٔ گرامری یا تفاوت معنایی واژه‌ها) + یک مثال جدید → کش شدن روی همان سؤال (پاسخِ همه یکسان و کنترل‌شده).
- **ارزش:** تمایز بی‌رقیب نسبت به وبکتاب‌های PDF-محور؛ عملاً «معلم خصوصی» داخل اپ.
- **پیچیدگی:** **Medium** — یک route با LLM skill + پرامپت قالب‌بسته + cache جدایی از rate-limit (مثلاً ۲۰/ساعت/کلاینت) + fallback متن ثابت «بررسی کن: X به‌عنوان اسم غیرقابل شمارش…».
- **ریسک:** هزینه و تأخیر → کش + قالب؛ هذیان مدل → پرامپت مقید «فقط بر اساس گزینه‌ها و کلید»؛ خروجی باید حداکثر ~۴۰۰ کاراکتر باشد.
- **فاز:** 🔵 فاز ۳ (بعد از استحکام حلقهٔ بازگشت) — ولی چون تمایزساز اصلی است، پیشنهاد: ساخت MVP آن در فاز ۲-۳ با ۱ دکمه در فقط موتور آزمون.

### F9 — نگهبان زنجیره (Streak Freeze + بازیابی) 🟢
- **مشکل:** زنجیرهٔ چندروزه با یک روز غیبت صفر می‌شود → ناامیدی → ترک دائمی (الگوی شناخته‌شدهٔ Duolingo).
- **سناریو:** کاربر فعال ۱ «یخ زنجیره» در هفته می‌سازد (با ۳ هدف کامل)؛ روز غیبت خودکار مصرف می‌شود؛ زنجیره حفظ می‌شود + پیام «یخِ تو نجاتت داد!».
- **ارزش:** ماندگاری؛ تبدیل شکست به نجاتِ قابل‌روایت.
- **پیچیدگی:** **Low** — منطق در محاسبهٔ day-streak موجود + دو فیلد در استور + UI کوچک.
- **ریسک:** کم؛ فقط باید ضد-آبُس (نمی‌تواند زنجیرهٔ بی‌پایان بسازد — سقف ۱ یخ فعال).
- **فاز:** 🟢 فاز ۲.

### F10 — زیرساخت اعتماد تکرارپذیر: Smoke Test + Analytics سبک 🔵
- **مشکل:** هیچ تست خودکاری نیست (جز rate-limit)؛ هر راند ریسک رگرسیون پنهان دارد؛ تصمیم‌های محصول بدون دادهٔ رفتاری کور هستند.
- **سناریو:** (الف) ۵ smoke test پایه (بارگذاری خانه، باز کردن درس و ۷ تب، یک دور آزمون، ثبت نتیجه در API) با Playwright؛ (ب) شمارندهٔ رویداد سبک سروری (بدون PII: open، lesson_open، quiz_done، rush_done) در جدول `Event` + داشبورد داخلی ساده.
